# 固定资产处置后的银行收款与催收交接 v1（asset-sale-collections）

本文件是本仓自有的整数分记账约定，不涉及任何外部会计准则。设备中心卖出
拆并改造过的设备后，`asset-lineage` 台账认列的出售所得只用来按出售事件
建立**应收本金**；货款是否真正到账，以银行行为准。本命令按实际到账核销
各笔应收的分期，在退扣窗口内按原收款凭证处理银行退扣，每月输出应收余额、
催收委托变更指令与可供下一批续跑的自包含交接包。沿用严格 JSON 输入、
8 MB 上限及“目标已存在即退出 2、原子新建”的发布约定；既有命令的输入、
输出与行为保持不变。

## 输入契约

根对象为以下两种**互斥**形态之一，禁止任何额外字段。

### 首次形态 `{lineage, terms, through_month, bank_rows}`

- `lineage`：完整的 `asset-lineage` 输入，交给现有资产承继台账原样校验
  并计算。银行侧的任何变动都不能改写资产台账；本命令只读取其计算结果。
- 应收以 `lineage` 事件中每条**正出售所得**的 `sell` 结果建立：
  - 应收键 `sale_id` 取出售事件 ID（不是设备 ID、原始投入 ID 或类别）；
  - 本金等于该事件的 `proceeds_cents`，不是账面转出额或处置损益；
  - 零所得出售不建应收；没有任何正所得出售时按非法输入处理。
- `terms`：1–1000 条 `{sale_id, installments}`，与应收**一对一**。
  每笔 `installments` 为 1–6 条 `{due_month, amount_cents}`：
  - 到期月为规范 `YYYY-MM`，不得早于出售月，同笔内唯一；
  - 每期金额为 1–10^12 的整数分；分期总额**恰好**等于该笔本金。
- 首次批次从 `lineage.as_of_month` 的次月开跑，初始没有到账、没有月末
  逾期观察和催收委托；`through_month`（含）覆盖 1–12 个月。

### 接续形态 `{checkpoint, through_month, bank_rows}`

- `checkpoint` 必须是本命令上一次成功报告里的交接包，可直接复制；本命令
  不要求证明来源，但仍完整复核格式、数值、引用与内部金额一致性，任何
  自相矛盾都按非法输入处理。
- 每批从上一个交接包所标截止月的次月开跑，不再接收原资产数据或历史银行
  流水，也不增设新的出售；跨度同样为 1–12 个月。
- 不读取任何其他本地文件来补状态。

### 银行行 `bank_rows`

- 每月至多 240 条，按业务键 `(month, seq)` 唯一；`seq` 为 1–1000000 的
  整数，同 seq 跨月允许；`month` 必须落在本批区间内。输入数组的排列不是
  处理顺序，运行时按月归集、月内按 `seq` 升序。
- 到账 `{month, seq, kind:"receipt", sale_id, amount_cents}` 与退扣
  `{month, seq, kind:"chargeback", receipt_month, receipt_seq,
  amount_cents}` 分别只接受列出的字段；金额均为 1–10^12 的整数分。
- 禁止隐式浮点、布尔值、重复 JSON 键、未知字段与非有限常量。

## 到账核销与退扣

- **到账**：对该笔应收按到期月从早到晚清偿尚欠本金，未到期也可提前偿付；
  多余款项作为**这笔到账自己的未用款**保留，不冲抵别的应收，也不自动
  动用别笔留下的未用款。
- **退扣**：必须引用一笔按业务顺序已经发生、且仍在退扣窗口内的到账，
  本次金额不得超过该笔到账尚未退掉的净额。允许对同一到账分多次退扣。
  - 到账于 M 月时，只允许在 M、M+1、M+2 月被退扣；M+2 月业务结束即
    不可逆，其后不得再引用。
  - 先从原到账的未用款退，再按该到账原先核销的**相反次序**撤回尚未被
    退掉的份额；撤回后相应分期重新欠款。
  - 不能撤走其他到账的核销；退扣不得把任何分期的欠款推到其约定本金以上。
- 任何时点成立的不变量（内置校验，违约即失败）：
  - 每笔应收：累计到账净额 = 已核销本金 + 未用款；
  - 每笔应收：已核销本金 + 尚欠本金 = 本金；
  - 每笔到账：到账金额 = 已退金额 + 未用款 + 尚未撤回的净核销份额。

## 月末催收

每月先按 `seq` 处理完全部银行行，再在月末决定催收指令，月中变化不发
指令。

- 分期在到期月之后才算逾期；必须在**紧邻的上个月末与本月末**都仍有正数
  逾期欠款，才允许交给催收中心。交接金额是本月末该期的全部欠款，不是
  两个月的较小值。
- 每笔应收最多有一个生效委托，列明全部获准追收的分期及金额。将本月获准
  清单与上月末已经生效的委托比较：
  - 无变有发 `open`；有变无发 `withdraw`（清单为空）；
  - 均非空但清单或金额变了发 `replace`，清单**整份替换**旧委托；
  - 完全相同则不发。
- 没有银行行的月份同样推进月末逾期观察与委托比较。

## 报告

顶层仅含 `through_month, periods, checkpoint`。

- `periods` 按月升序，保留没有任何流水的空月；每月一项
  `{month, accounts, collection_orders}`。
- 每笔应收一行，按 `sale_id` 升序：
  `{sale_id, received_net_cents, applied_cents, unapplied_cents,
  outstanding_cents, installments}`，其中 `installments` 为
  `{due_month, open_cents}` 并保留已清偿期（`open_cents` 为 0）。
- 指令行 `{sale_id, action, installments}` 按 `sale_id` 升序；
  `installments` 同样为 `{due_month, open_cents}`，只列获准追收的分期，
  撤回时为空；分期一律按到期月升序。

## 交接包 `checkpoint`

自包含对象，可直接复制进接续输入，记录格式版本
（`format_version`）、截止月（`through_month`）和精确续跑所需的业务
状态：各应收的约定本金、各期约定本金与当前欠款、累计到账/退扣/核销/
未用汇总、上月末逾期观察、生效委托，以及仍在退扣窗口内到账的识别键与
核销明细。

- 出纳工作区交接后不保留以前的银行行；交接包不得塞入原资产输入或原样
  银行行来变相归档。
- 过了退扣期限的到账只保留其对账户余额的汇总影响：在其 M+2 月月末处理
  完后清除该笔的识别键、逐笔金额与核销明细；已经开始等待催收或正在催收
  的分期通过应收级状态保留连续性，不因此丢失。
- 接续时复核：格式版本、月份与跨度、金额取值区间、引用完整性、到账部件
  加总、逐笔活明细不超过账户汇总，以及上述全部金额不变量。
- 输入相同的连续月份时，一次处理与在任意月末拆批、只带交接包继续处理，
  合并后的月报与末次交接包完全一致。

## 输出与失败约定

非法输入（含资产台账校验失败、回放较晚才发现的引用错误、交接包内部
矛盾）或输出目标已存在时退出码 2，不发布部分结果且保留旧目标；全部
校验与计算完成后，报告与交接包作为**同一份 JSON**，通过同目录临时文件
原子硬链接新建，成功退出 0。
