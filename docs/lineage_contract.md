# 资产拆并改造后的价值承继 v1（asset-lineage）

本文件是本仓自有的整数分记账约定，不涉及任何外部会计准则。设备中心把一台
设备拆成几台独立入账的设备，或把几台设备合装成一台；改造只是把还没有消耗
的账面价值换个归属，不是重新采购。`asset-lineage` 从原始入账与改造、出售
事件生成价值承继清单和按月台账，与 `asset-schedule` 共用同一套整月折旧
规则、严格 JSON 输入、8 MB 上限及“目标已存在即退出 2、原子新建”的发布
约定；既有四个命令的输入、输出与行为保持不变。

## 输入契约

根对象仅含 `from_month`、`as_of_month`、`assets`、`events` 四个字段。

- 两个月份均为规范 `YYYY-MM` 字符串，均含在报告内；区间跨度 1–120 个月，
  从零期初开始（期初没有任何在册设备）。
- `assets` 为 0–200 条原始投入记录，使用 `asset-schedule` v1 的资产字段、
  数值校验与单位（`id`、`category`、`cost_cents`、`salvage_cents`、
  `life_months`、`in_service_month`、`disposal`），另要求投入月在报告区间
  内、`disposal` 为 `null`；出售统一通过 `sell` 事件输入。
- `events` 为 0–1000 条事件的数组，排列不表示先后。每条事件有唯一 `id`
  （非空字符串，不超过 200 字符）、区间内的 `month`、同月唯一的正整数
  `seq`（1–1000000）和 `kind`；除此之外只接收对应类型的字段：
  - `reconfigure`：`sources` 为 1–8 个不同的当前设备 ID；`targets` 为
    1–8 条 `{id, category, weight}`，`id` 与 `category` 沿用资产记录的
    字符串限制，`weight` 为 1–10000 的整数，只有一个目标时须为 1。
    源与目标两侧至少一侧只有一项：可以拆分、合装或一换一，不做多对多事件。
    目标 ID 不得与任何原始资产或其他事件的目标 ID 相同，即使该 ID 还未
    生效或已经注销也不能使用。
  - `sell`：`asset_id` 为一台当前设备的 ID，`proceeds_cents` 沿用原命令
    金额上限（0–10^12 的整数分）。
- 资产、事件 ID 和类别均按原字符串精确比较。禁止隐式浮点、布尔值、重复
  JSON 键、未知字段与非有限常量。

## 生效顺序

每月先认列该月原始投入（设备启用并计入 `acquired_cents`），再按 `seq`
依次处理该月事件，最后只给仍在册的设备计提该月折旧。

- 改造事件的源设备全部注销、目标设备全部启用；新设备在改造事件后立即可
  用于下一笔事件，注销设备不能再使用，即使其后事件发生在同一个月。
- 是否在册不以价值是否为零判断：零值设备仍在册，可作源、可作目标、须列
  入月表。
- 旧设备不补提本月折旧：当月尚未计提的价值随改造转移，或在出售时一并
  转出。出售后注销该设备，被转出的任何金额不再计提。
- 设备是否在册、能否被事件引用在回放时判定；回放较晚才发现的引用错误
  同样按非法输入处理。

## 价值承继

每笔原始投入按 v1 整月直线规则确定各使用月的折旧金额与寿命结束后保留的
残值：第 i 个使用月折旧为 `floor((cost-salvage)*i/life)` 的累计差额，满
寿命精确折到残值。尚未计提的金额保留**原始投入 ID** 和**原应计月份**，
残值始终与各月折旧分开承继。报告可以只到某个中间月，但任何时点的账面
价值都必须含尚未到期的折旧金额和残值，不能以报告月截断。

- 改造不改变已计提的折旧。合装时，同一原始投入在多台源设备上的份额，
  如果属于同一应计月（或都是残值），在目标设备上合并为该原始投入的一
  笔金额；不同原始投入不可合并成一个折旧口径。
- 拆分时，分别对每个原始投入的每个尚未计提月份、以及该原始投入的残值
  按权重分配整数分：各目标先拿其精确份额的整数部分，剩余每分依份额的
  小数部分从大到小给不同的目标，小数部分相同时 ID 字典序较小者先拿。
  不能把同一笔原始投入的多个旧路径当作独立金额各自取整，也不能先合计
  不同原始投入再分。
- 各笔未计提金额连同残值在改造前后各自守恒；全仓每月改造转入等于改造
  转出。
- 出售时，处置账面价值为该设备事件发生时持有的全部剩余价值；所得减去
  转出价值为处置损益（可为负）。

## 报告

报告顶层仅含 `from_month`、`as_of_month`、`events`、`periods`。金额全部
为整数分；转入、转出、折旧、成本和所得均用非负金额，损益可为负。

- `events` 按月和序号排列，每行包含 `month, seq, id, kind`。改造行提供
  `sources`、`targets`，逐设备列出本次移出的、移入的账面值，每侧分别按
  设备 ID 升序；出售行提供 `asset`（被出售设备的转出明细）、
  `proceeds_cents`、`gain_loss_cents`。每条设备明细包含
  `asset_id, carrying_cents, by_origin`，其中 `by_origin` 是原始投入 ID
  到非零金额的映射，金额之和等于该行账面值；零值设备也要保留明细。
- `periods` 按月升序，保留空月。每行含 `month`、按 `asset_id` 升序的
  `assets` 及以类别为键的 `categories`。当月任何时点在册的设备均列出，
  包括当月启用又注销及零值设备；类别按当月资产行汇总同一组指标。每行
  提供 `opening_book_cents, acquired_cents, transfer_in_cents,
  transfer_out_cents, depreciation_cents, carrying_removed_cents,
  proceeds_cents, gain_loss_cents, closing_book_cents`。
- 原始投入计入 `acquired_cents`，改造不能计作投入或处置。期末账面等于
  期初加投入、加改造转入、减改造转出、减折旧和处置转出。月表转入、转出
  和处置金额须与事件明细逐设备对平（程序内置对账校验，不平即按失败
  处理）。

## 输出与失败约定

非法输入（包括回放较晚才发现的引用错误）或输出目标已存在时退出码 2，
不发布部分报告且保留旧目标；全部校验与计算完成后，通过同目录临时文件
原子硬链接新建一份完整 JSON 报告，成功退出 0。
